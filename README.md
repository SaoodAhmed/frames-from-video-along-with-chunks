# FrameForge — Production Video Frame Extractor

A production-ready, multi-user web application that extracts frames from uploaded videos.
Built for Cloudflare (Workers + D1 + R2) with a serverless Python/OpenCV processor on Modal.

The extraction engine is ported 1:1 from the original desktop app (`images_from_video-3.py`).

## Architecture

```
Browser ──(presigned multipart PUT)──▶ R2 (video objects, private)
   │                                      ▲
   │  JSON API (auth, job/upload mgmt)    │
   ▼                                      │
Cloudflare Worker (Hono) ────────────────┘
   │  D1 metadata (users, jobs, frames, exports)
   │  webhook (fire-and-forget)
   ▼
Modal Python processor (OpenCV)
   │  streams frames → full + thumbnail JPEGs → R2 → D1 rows
   │  ZIP export → R2
   ▼
Admin Portal (private)  —  User Portal (upload + track only)
```

- **No video bytes pass through the Worker.** Uploads go browser → R2 directly via
  AWS SigV4 presigned URLs generated by the Worker.
- **Users upload only.** All processing (extraction settings, queue, exports) happens
  in the private admin portal.
- **State machine** (`uploaded → queued → processing → completed/failed/cancelled`)
  is enforced by guarded atomic SQL transitions, shared by the Worker and the processor.

## Repo layout

```
frontend/            Static assets served by the Worker (user + admin portals)
worker/src/          Hono Worker: routes, auth (JWT + PBKDF2), SigV4 presigner, D1
worker/test/         Integration tests (vitest + @cloudflare/vitest-pool-workers)
migrations/          D1 schema + indexes
processor/           Modal Python processor (OpenCV frame extraction, ZIP export)
wrangler.toml        Worker + D1 + R2 configuration
```

## Prerequisites

- Node 18+ and npm
- A Cloudflare account with the D1 database and R2 bucket created (see `.env.example`)
- The `.env` file at the repo root with the **real** Cloudflare credentials (never commit it)
- (Optional, for processing) a Modal account and the `modal` CLI

## Local development

Install dependencies:

```bash
npm install
```

Copy the example env into `.dev.vars` (used by `wrangler dev`) and fill in real values:

```bash
cp .env.example .dev.vars
```

Apply migrations to the local D1 (SQLite) and start the dev server:

```bash
npm run migrate:local
npm run dev            # serves http://localhost:8787
```

The user portal is at `/`, the admin portal at `/admin.html`. To create the first
admin, run the bootstrap against the local server:

```bash
ADMIN_SETUP_TOKEN=<your-token> npm run seed:admin -- --email admin@example.com --password 'S3curePass!'
```

## Tests

The suite runs against real Miniflare D1/R2 bindings (in-memory, isolated per test):

```bash
npm test
```

Coverage: auth (register/login/admin bootstrap + 401/403), uploads (presigned
multipart create/complete/delete), job processing presets & state transitions,
frame listing/soft-delete, ZIP export, and cross-user isolation.

## Deploying

Set the Worker secrets (never in `wrangler.toml`):

```bash
wrangler secret put AUTH_SECRET
wrangler secret put ADMIN_SETUP_TOKEN
wrangler secret put R2_ACCESS_KEY_ID
wrangler secret put R2_SECRET_ACCESS_KEY
wrangler secret put R2_ENDPOINT
wrangler secret put R2_BUCKET_NAME
wrangler secret put D1_DATABASE_ID
```

Apply migrations to production D1, then deploy:

```bash
npm run migrate:prod
npm run deploy         # or: wrangler deploy
```

Bootstrap the first admin against the live site:

```bash
ADMIN_SETUP_TOKEN=<one-time-token> node worker/scripts/seed-admin.mjs --url https://your-domain --email admin@example.com --password 'S3curePass!'
```

Delete the `ADMIN_SETUP_TOKEN` secret after bootstrapping to lock the route down.

### Modal processor

The processor reads D1 over HTTPS and writes R2 via boto3 — it needs its own secret
group, a staging volume, and a deploy from `processor/`:

```bash
pip install modal
modal token new
modal secret create frameforge-secrets \
  PROCESSOR_R2_ACCOUNT_ID=... PROCESSOR_R2_ACCESS_KEY_ID=... \
  PROCESSOR_R2_SECRET_ACCESS_KEY=... PROCESSOR_R2_BUCKET=... \
  PROCESSOR_R2_ENDPOINT=... PROCESSOR_D1_ACCOUNT_ID=... \
  PROCESSOR_D1_DATABASE_ID=... PROCESSOR_D1_API_TOKEN=... \
  PROCESSOR_WEBHOOK_TOKEN=<shared with MODAL_TOKEN>
modal volume create frameforge-staging
modal deploy app.py
```

Then tell the Worker how to trigger it (both are optional — the processor also runs
a scheduled sweep as a safety net for queued jobs):

```bash
wrangler secret put MODAL_PROCESS_URL   # https://<workspace>--frameforge-processor-webhook.modal.run
wrangler secret put MODAL_TOKEN         # same as PROCESSOR_WEBHOOK_TOKEN
```

## Security notes

- R2 is private; browsers only get short-lived presigned URLs (15 min).
- Passwords are PBKDF2-SHA256 (100k iterations); sessions are HS256 JWTs via WebCrypto.
- Role-based auth: `requireAuth` (401) vs `requireAdmin` (403).
- User isolation: job/frame queries are always scoped by `user_id`; admin-only routes
  never leak another user's data.
- Filenames are sanitized; MIME types and upload sizes are validated server-side.
- Best-effort in-memory rate limiting on `/api/auth/*`; enable Cloudflare WAF rules
  on the zone for hard production limits.
